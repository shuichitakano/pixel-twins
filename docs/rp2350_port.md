# RP2350移植設計

## 共通コードと境界

`pixel_twins`ターゲットはmacOS版とRP2350版で同じ`src/`をビルドします。
BG、スプライト、プリミティブ、フォント、フレームバッファ、音源、
シーケンサの代替実装は作りません。

RP2350固有実装は`platform/rp2350/`に限定し、次の完成済みデータの入出力だけを
担当します。

- `Framebuffer::displayBuffer()`と`Palette`からLED転送データを生成・転送
- USBホストから2人分の`ControllerSample`を生成
- `AudioSystem::renderBlock()`で生成した48kHz、16-bitステレオPCMを転送
- ボードのタイマと初期化

## ビルド

Pico SDKの標準的なクロスビルドとホステストを分離します。

```sh
PICO_SDK_PATH=/path/to/pico-sdk cmake -S examples/rp2350 -B build-rp2350 \
  -DPICO_BOARD=pico2 -DCMAKE_BUILD_TYPE=Release
cmake --build build-rp2350 --parallel
```

`pixel_twins::rp2350`はPico SDKと共通ライブラリの依存境界です。RP2350ビルドでは
SDLサンプルとホステストを既定で無効にします。

## SRAM配置

`PIXEL_TWINS_SRAM`を付けた描画、フリップ、音声生成関数はRP2350ビルドで
`.time_critical.pixel_twins`セクションに配置され、起動時にSRAMへコピーされます。LED転送実装も
同じ属性を付けます。リンク後はMAPファイルで対象関数の配置を検査します。

## LEDパネル

### 接続

LEDデータはPIOからGPIO2〜13へ12bit同時に出力します。ビットと信号の対応は次の通りです。

| PIO出力bit | GPIO | 信号 | 画素 |
| ---: | ---: | --- | --- |
| 0 | 2 | R1 | 左パネル上側 |
| 1 | 3 | R2 | 左パネル下側 |
| 2 | 4 | G1 | 左パネル上側 |
| 3 | 5 | G2 | 左パネル下側 |
| 4 | 6 | B1 | 左パネル上側 |
| 5 | 7 | B2 | 左パネル下側 |
| 6 | 8 | R3 | 右パネル上側 |
| 7 | 9 | R4 | 右パネル下側 |
| 8 | 10 | G3 | 右パネル上側 |
| 9 | 11 | G4 | 右パネル下側 |
| 10 | 12 | B3 | 右パネル上側 |
| 11 | 13 | B4 | 右パネル下側 |

制御信号は`CLK=GPIO14`、`LAT=GPIO15`、ライン選択の`A/B/C=GPIO16/17/18`、
`OE=GPIO19`です。GPIO14と15が連続しているため、データPIOはCLKとLATを2bitの
side-setとして同時に制御します。

### パネル内の転送順

GS6263は16出力、12bit階調で、データとしては画素ごとに16bit分を受け取ります。
先頭4bitを0、その後に12bit階調値をMSB-firstで送ります。1ラインは16出力のドライバを
10個カスケードして160ピクセルを構成するため、フレームバッファの参照順は単純な
`x=0..159`ではなく、次の順です。

```text
for output = 0..15
    for cascade = 0..9
        x = cascade * 16 + output
        16bit分の階調データを送る
```

各走査ラインでは次の4画素を同時に読み、1クロック分の12bitへ合成します。

```text
左パネル上側: (x,       y)
左パネル下側: (x,       y + 60)
右パネル上側: (x + 160, y)
右パネル下側: (x + 160, y + 60)
```

この処理を`y=0..59`について行い、2枚の160×120パネルを更新します。

### パレット変換テーブル

フレームバッファは8bitインデックスカラーなので、256色のパレットから直接LED転送用
テーブルを作ります。1色につき、RGBの12bit階調を16クロック分の位置へあらかじめ
配置します。

PIOの32bit OSRは12bitの`out`をワード境界越しに連結できないため、autopull thresholdを
24bitとし、1ワードへ2クロック分を格納します。上位8bitは使用しません。

```text
bit  0〜11: 1クロック目の12bit
bit 12〜23: 2クロック目の12bit
bit 24〜31: 未使用
```

1エントリは32bitワード8個で、テーブル全体は8,192バイトです。

テーブルの基準位置は左パネル上側のR/G/B、すなわちbit 0/2/4です。同時に読む4画素の
テーブルを各ワード内でそれぞれ0、1、6、7bitシフトしてORすると、そのままPIOへ送る
12bit並列ストリームになります。ワードをまたぐcarry処理、RGBごとの抽出処理、3本のDMA、
3つのPIO SMの同期処理は不要です。

### PIOとDMA

LEDデータPIOは1つのSMでGPIO2〜13を`out pins, 12`し、GPIO14/15へCLK/LATを
side-setします。通常クロックは2命令で出力し、160クロック目だけLATを立てます。
FIFOに転送データがない間もCLKを出し続けます。

CPUは走査ライン2本分の転送バッファを交互に使用します。一方をDMA転送している間に
次の走査ラインを生成するため、全画面分の変換済みバッファは保持しません。使用する主な
固定領域は次の通りです。

| 領域 | 容量 |
| --- | ---: |
| パレット変換テーブル | 8,192バイト |
| 走査ラインバッファ2本 | 10,248バイト |
| 固定コマンド列 | 約2.1KiB |

別のPIO SMは`A/B/C/OE`を使い、60ラインの選択とGS6263のPWMクロックを生成します。
初期設定、VSync、表示バッファ切り替え用コマンドは従来のGS6263コマンド列を使用し、
両パネルへ同時に送ります。

PWM走査は35周を1表示周期として約60Hzに設定します。DMA完了だけではPIOのFIFOとOSRに
未出力データが残ります。また、FIFOが空になった後もOSRには次の1周分が先読みされており、
PIOのPCは周回境界で先頭命令を一瞬通過するため、PCだけでも終了を判定できません。

DMA完了直後は最後のPWMワードがまだFIFOまたはOSRに残っていることを利用し、この時点で
`TXSTALL`をクリアしてから、新しく発生するstallを待ちます。これによりOSRの先読み分を含む
全周回の終了を一意に判定してから次のVSyncコマンドへ進みます。ゲーム統合時はcore 1が
次の`present()`を直ちに開始するため、core 0の描画中にもPWMクロックが継続します。

### 実機テストパターン

`examples/rp2350`は252色のパレットから作った8×8ピクセルの色タイルを、毎フレーム
1ピクセルずつ横スクロールします。タイルの縦位置を4ラインずらしてy=59/60をタイル境界に
合わせているため、左右パネル境界での転送順に加え、上下走査領域の折り返しだけに生じる
乱れも目視で切り分けられます。

PWM PIOは一連の走査を終えると、ライン0を選択した状態でFIFO待ちになります。このとき
ラインドライバ出力を有効のままにすると、OEクロックが止まった瞬間のGS6263出力状態が
保持され、y=0/60だけが過点灯します。このためPWMバッチ末尾ではBをhighにしてライン出力を
無効化し、次のバッチの最初のPWMクロック直前にのみlowへ戻します。
